Start here

One command, a herd of agents

One command sets up herdr with one-key agent launchers and a fleet command to run and drive several AI coding agents at once. This page shows what it installs, how to use it, and how to plan a fleet before you start.

Install

macOS or Linux. Safe to run again.
curl -fsSL https://raw.githubusercontent.com/mrx-arafat/herdr-setup/main/install.sh | sh

Downloads install.sh and runs it. It asks before it installs the herdr-plus plugin. Installing a plugin clones a GitHub repository and runs its build script, so read what you install.

curl -fsSL https://raw.githubusercontent.com/mrx-arafat/herdr-setup/main/install.sh | sh -s -- --yes

--yes skips the plugin question. Use it in scripts, or when you already know you want herdr-plus.

curl -fsSL https://raw.githubusercontent.com/mrx-arafat/herdr-setup/main/install.sh -o install.sh
less install.sh
sh install.sh

Download, read, then run. Nothing is installed until you run the last line.

The launchers turn permission prompts off. They start agents with their permission prompts or sandbox off, so an agent can edit files and run commands without asking. Codex's own help calls its flag “EXTREMELY DANGEROUS. Intended solely for running in environments that are externally sandboxed.” Use them in git repos with a clean working tree, so you can review or discard every change. To keep the prompts, set FLEET_CLAUDE_ARGS="" (and FLEET_CODEX_ARGS, FLEET_AGY_ARGS) when you run fleet up.
FLEET_CLAUDE_ARGS="" FLEET_CODEX_ARGS="" FLEET_AGY_ARGS="" fleet up 4 1 claude,codex,agy

Quick Actions always start agents with their checks off. To keep the prompts, run fleet up from a terminal, as above. The planner builds this command for you.

Requirements

jqbrew install jq or sudo apt install jq
curlDownloads the scripts
An agentAt least one CLI, signed in: claude, codex or agy

Check what you have:

for t in herdr claude codex agy jq curl; do printf '%-8s ' "$t"; command -v "$t" || echo "not found"; done

herdr, jq and curl are required. Of the three agents, one is enough.

What the installer does

  1. Checks that herdr 0.7.0 or newer, jq and curl are installed.
  2. Installs the herdr-plus plugin (herdr plugin install cloudmanic/herdr-plus) after asking you. It asks on your terminal even when piped, and --yes skips the question.
  3. Downloads two scripts (agent-tab.sh, fleet.sh) and six Quick Actions from this repo into ~/.config/herdr/plugins/config/cloudmanic.herdr-plus/. It never overwrites a file that exists.
  4. Links the fleet command into ~/.local/bin when that folder is on your PATH, otherwise prints an alias line. It never replaces an existing fleet command.
  5. Binds prefix+up to Projects and prefix+down to Quick Actions in ~/.config/herdr/config.toml, after a timestamped backup. It skips keys you already use.
  6. Reloads herdr and runs herdr config check.

Safe to run again.

Try it in 30 seconds

  1. Open herdr in a project folder: cd into it and run herdr.
  2. Press ctrl+b then ↓. Type claude and press Enter. A new tab runs Claude with prompts off.
  3. Press ctrl+b then ↓ again. Type workers, pick Workers, then 2 workers. A tab named workers opens with two Claude panes, w1 and w2.
  4. In another pane run fleet ls to see the workers.

Manage & clean

        
Keep the workspace tidy

        
See what is running, reset a worker's memory, close what you are done with, and keep the setup healthy.

      

      

        

          
See what is running safe

          
Workers with agent, status, tab and pane. The sidebar shows the same states for every workspace.

          
fleet ls
fleet focus w3
herdr agent list

          
Jump anywhere: ctrl+b g, or ⌘P in the Herdr app.

        

        

          
Reset memory loses context

          
Claude and Codex workers get /clear, a fresh chat in the same session. Claude's counter then reads 0 tokens. Old text stays in the scrollback.

          
fleet clear w2
fleet clear all

          
Agy has no verified clear command. Close and relaunch it instead.

        

        

          
Close workers ends sessions

          
Closing a worker ends its agent. When a tab's last pane closes, the tab goes too. all asks first.

          
fleet close w3
fleet close all
fleet close all --yes

Weekly maintenance

          

          

        

        

          
Parallel work without collisions

          
One worktree per task: a separate checkout on its own branch, opened as its own workspace with a claude tab ready.

          
cd ~/code/my-app
for task in login-form rate-limit audit-log; do
  herdr worktree create --cwd "$PWD" --branch "feat/$task" --no-focus
done
herdr worktree list

          
Pick branch names you want to keep. git worktree prune drops records of worktrees whose folder is gone.

Add your projects
ctrl+b then ↑ opens the picker

          
A project is one TOML file in ~/.config/herdr/plugins/config/cloudmanic.herdr-plus/projects/. Pick it in the picker and herdr builds its workspace with the tabs you listed. New files appear the next time you open the picker.

          
D="$(herdr plugin config-dir cloudmanic.herdr-plus)/projects"
mkdir -p "$D"
cat > "$D/my-app.toml" <<'EOF'
name = "my-app"
description = "~/code/my-app"
working_dir = "~/code/my-app"

[[tabs]]
name = "claude"
command = "claude --dangerously-skip-permissions"

[[tabs]]
name = "terminal"
EOF

          
The folder must exist. Change the paths to your own project.

        

        

          
Project file fields

          

            
FieldWhat it does

            
              
nameThe name shown in the picker.

              
descriptionOptional grey text next to the name.

              
working_dirWhere every tab starts. ~ and $VARS expand. The folder must exist.

              
[[tabs]]One tab. Tabs open in file order.

              
nameInside a [[tabs]] block: the tab label.

              
commandInside a [[tabs]] block: typed into the tab's shell and run. Leave it out for an empty shell.

Worktree layout
optional

          
With a worktree layout, every new herdr worktree opens ready, for example with a claude tab and a terminal tab. The installer does not turn it on. Copy files/worktrees/default.toml from this repo into the plugin folder's worktrees/ folder to enable it. Delete the file to turn it off.

          
D="$(herdr plugin config-dir cloudmanic.herdr-plus)/worktrees"
mkdir -p "$D"
cp files/worktrees/default.toml "$D/"   # run from a clone of this repo

Working agreement

        
Rules worth giving your agents

        
With permission prompts off, written rules are the safety net. This is a starting point. Put the rules in the file your agent reads, and edit them to match how you work.

hard stops

    •

Where agents read rules

          
    
            
  • Claude Code reads CLAUDE.md (~/.claude/CLAUDE.md for every project).
    • 
            
  • Codex reads ~/.codex/AGENTS.md, plus AGENTS.md files from the project root down.
    • 
            
  • Agy and Gemini read ~/.gemini/GEMINI.md.
    • 
          

          
Keep one ~/AGENTS.md and copy it with files/extras/sync-agent-rules from this repo. It is a script that writes a marked block into the Codex and Gemini files and leaves everything else in them alone. It is not installed by default. Run it once, and again after every edit to ~/AGENTS.md.

          
cp files/extras/sync-agent-rules ~/.local/bin/ && chmod +x ~/.local/bin/sync-agent-rules
sync-agent-rules

          
Run it from the root of a copy of this repo. The second line is the one to rerun later.

        

        

          
Starter rules
Markdown. Edit freely.

          
# Rules for coding agents

## Ask first
- Never run destructive database commands without asking first, even on staging.
  This includes migrate:fresh, db:reset, DROP, TRUNCATE and DELETE without a WHERE.
- Never run git add, commit, push, pull, merge, rebase, reset, stash or checkout unless I ask.
- Never create or switch branches unless I ask.
  Push new branches with git push -u.

## Workflow
- Plan before large changes.
- Reproduce a bug before fixing it.
- Write a failing test first.

## Tests and proof
- Run only the tests that cover your change.
  CI runs the full suite.
- Passing tests are not proof.
  Run the program.
- Check visible changes in a real browser.

## Docs
- Update the docs in the same change as the code.
